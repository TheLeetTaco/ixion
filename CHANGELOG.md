### Added

- **`ship` can arm GitHub auto-merge on the PR it just opened.** After `gh pr create` succeeds, Phase 4 resolves a four-valued `automerge=` — `off`, `deferred`, `immediate`, `unknown` — from the repository's `allow_auto_merge` flag and the PR's `mergeStateStatus`, then asks **once**, tagged Irreversible, before running `gh pr merge --auto --squash --delete-branch`. **Arming is confirmed, never automatic**, and the confirmation's outcome line says which of the two things will happen: `deferred` merges unattended once the gate clears, `immediate` merges on the spot because nothing is gating the PR. On approval the state is read once more, since `AskUserQuestion` waits on a person: arming happens only where it still matches what the confirmation quoted, and a state that drifted while the question was open is reported instead of armed. `off` and `unknown` ask nothing and arm nothing — `off` names the repository setting's location without offering to flip it, `unknown` reports the state where it read one and says availability could not be confirmed where it did not, printing the arming command for later either way. There is no poller and no session held open; the session is still marked `status: completed` and the session worktree is still the user's to remove. `gh pr merge --auto` cannot be called blind: with the repository setting off (cli/cli#8792) or with nothing gating the PR (cli/cli#13880) it merges immediately without erroring, which is why the probe exists. See the amendment in `docs/adrs/0001-skill-design-as-negotiation.md`.

### Changed

- **`ship` compounds learnings before it pushes, and commits what compound wrote.** Phase 5 wrote solution docs into the session worktree *after* `gh pr create` had already opened the PR, so `docs/solutions/` — a tracked directory — was left uncommitted in a tree whose removal command the same phase hands the user; `git worktree remove` refusing a dirty tree was the only thing between those docs and deletion. This repository hit it on its own 4.2.0 session: the learnings went out as a second branch and a second PR (#4) beside the work they belonged to (#3). Compounding is now Phase 4, ahead of the push, and ends by committing `docs/`, `AGENTS.md` and `CLAUDE.md` onto the session branch, so the lesson ships in the PR that produced it. Nothing else about the phase changed.
- **`work-review` supports an ad-hoc review, and never writes findings into a session the invocation didn't name.** Its description has always advertised "a session's work, a branch, or the current changes," but only the first was wired: a branch argument or a bare invocation with no session still resolved a session through `active.json`, reviewed `base_ref..HEAD` of whatever checkout it was standing in rather than the named branch, and wrote `review.findings.json` into that session — which is precisely the file that starts that session's next `/work` on a fix pass, now carrying another branch's findings. Phase 0 now resolves `kind=` (`session`, `branch`, `checkout`) together with the `tree=` to stand in and the `out=` to write to, in one block; `via=none` stops halting, exactly as in `ship`, because an ad-hoc review is a supported way to use the skill. An ad-hoc review measures its diff from the integration branch, is dispatched with `PLAN CONTEXT: none`, skips drift arbitration (there is no spec to have drifted from), and writes into `.ixion/plugin/reviews/<branch>-<date>/`. Four more `kind=` values stop with a message of their own, including `not-checked-out` — a branch no worktree holds cannot be reviewed, because the empirical gate's commands need a tree with dependencies installed.
- **`plan-review` takes a session locator and nothing else.** The "readable path" form skipped session resolution, which left its own write target `<dir=>/review.findings.json` unbound and its resume line naming a `plan-consolidation` that had no session to consolidate. A plan document now has one route, the one that works: `/ixion:plan <path>` turns it into the `spec.json` this skill reviews and consolidation refines.
- **Every worktree-bound block stands in the session worktree by name.** The session worktree is a sibling of the repository root, which is outside the directory Claude Code was launched in; a Bash `cd` there is reset to the project root before the next call, and a dispatched subagent starts at the project root regardless. The three callers had said "`cd` in and run the rest from there." Now each block in `work`, `work-review` and `ship` that reads HEAD or the working tree opens with `cd '<worktree=>' || exit 1`, `work`'s dispatch addendum hands every subagent the absolute path and the per-call `cd` rule, reviewer dispatches name the source root absolutely, and `session-handoff.md`'s "Derive the session worktree" section carries the reason once. `07` asserts the chunk commits landed in `<sandbox>-<slug>`. See the amendment in `docs/adrs/0001-skill-design-as-negotiation.md`.
- **`plan-review` hands reviewers the spec by absolute path, never inline.** A 30–60 KB spec pasted into six dispatches was the largest single emission in the pipeline, all of it output tokens in the orchestrator's own context; reviewers Read the file in full instead, for the reason `reviewer-dispatch.md` already gives for the reference sections.
- **`work-review` stages the diff once and verifies anchors.** The diff is written to `<session>/review.diff`, reviewers Read it by path and are told every `location` is a SOURCE line verified in the worktree — never a diff offset — and the synthesizer confirms each `path:line` is in range, re-anchoring by grep where it is not. This lands the fix `docs/solutions/mistakes/reviewers-given-a-diff-file-cite-diff-offsets-System-20260804.md` recorded and the skill never carried.
- **Research agents no longer preload `ixion-conventions`; reviewers are told `language-standards` is preloaded.** The four locators and five analyzers restate every rule they used from the conventions file in their own definitions, and a locator has no Skill tool to reach the rest with. The six reviewers preload `language-standards` via frontmatter and were also told to load it — two copies per reviewer per round. Locators also drop the `LS` tool, which Claude Code does not ship.
- **`progress.json.status` reaches `completed` only in Phase 5.** The checkpoint that finished the last chunk used to write it before Phase 3's criteria and Phase 4's self-check had run, so an interruption there left a session the fix-findings transition would accept unverified. 2.3 now always writes `in_progress`; Phase 5 writes `completed` before its prompt, so a `/clear` at the prompt still leaves a finished session.
- **`plan-review` converts opposing recommendations into one open question (new 2.3a).** `references/conflict-handling.md` was cited from the skill's footer and run from no phase, so two reviewers prescribing opposite changes both integrated. The severity-disagreement row is gone from that reference and from `plan-consolidation` Phase 3: dedup already takes the maximum and every surviving finding integrates whatever its tier.
- **CI runs the three offline harnesses** and shellchecks them.

- **Reviewers load `language-standards` on demand instead of preloading it.** All six carried it in their `skills:` frontmatter, which preloads the full text into every reviewer on every round — and the skill is Rust-only, so on any other repository that is dead weight six times a wave, twice a pipeline. `user-invocable: false` gates slash commands, not the Skill tool, so the load works on demand; each reviewer now carries a concrete trigger ("if the change includes Rust — any `.rs` file, or `Cargo.toml` — load it now and apply these sections; if not, skip it") rather than an unconditional instruction. `ixion-conventions` stays preloaded, because every reviewer uses it on every finding.
- **The claim block dates the session id itself.** `<slug>-<YYYY-MM-DD>` left both halves to the model, and the year was propped up by four `**Note: The current year is 2026.**` lines that go wrong on 1 January. The block now computes `date -u +%F` and only `<slug>` is filled in; the four notes are gone, with the two analyzers that used one keeping a recency instruction that names no year. `tests/session-resolution-harness.sh` builds its expectations from the same `date -u +%F` and hand-creates the one fixture that needs a second, older date.
- **The ADR's amendments moved to `docs/adrs/0001-amendments.md`.** `CLAUDE.md` inlines ADR-001 with `@` on every turn of every session in this repository, and the file had grown to 80 KB — of which 46 KB was the narrative of how each mechanism reached its shape, which is what you consult when changing a mechanism, not what binds while using one. The fourteen principles, the standing rejections in "Considered and deferred" and the Related-work index stay inlined at 34 KB; the change log is one link away. Rationale Discipline applied to our own operator file.

- **`work` names the two improvised shapes that destroy a session artifact, and 2.0 refuses to compute a wave without a worktree.** Observed live on 2026-08-21: after a full `/ixion:plan` pipeline, `work` Phase 1 wrote a session field with a hand-authored `jq` line instead of the block it was told to paste — `jq` is not installed and 4.0 removed the dependency — and because the line redirected into `session.json`, the shell truncated it to zero bytes before `jq` failed. Recovering the file displaced the worktree step that follows, so the session got no worktree and no branch, and its checkpoint commit landed on `main`; the main agent then implemented the feature itself rather than dispatching a subagent. `session-handoff.md` now names both shapes at the block they replace and states that `wrote=` is the receipt for a write having happened; `work` Phase 1 repeats it once for the five writes it makes; and 2.0 checks `branch=` before computing a wave, because that is the step whose absence sends every later commit to the wrong branch. Nothing here is a new validator — the invariant `git grep -nwE 'jq' -- ixion/` was already true and is now written down where it is violated.

- **`work-review` 2.4 names the misroute the ad-hoc destination made possible.** Adding a second write destination gave a recalled Phase 0 somewhere wrong to land: observed 2026-08-21 writing a resolved session's findings to `.ixion/plugin/reviews/<session-id>/` — a path that is neither destination, composed from the session id — where `work` never looks, leaving the session reviewed on paper and unreviewed in fact. 2.4 now says the reviews directory belongs to `branch` and `checkout` alone and that `out=` is the answer, and Phase 0 repeats the paste-don't-recall line `work` Phase 1 carries.

### Fixed

- `ixion-conventions`' Spec Quality Bar told the planner to mark a phase `status: deferred`; `spec.schema.json` rejects the field. It now routes the gap to `open_questions[]`.
- `plan` resolved the session without first resolving the session root every other caller binds.
- `06-parallel-chunks` ran its implementation assertion in the sandbox, which under one-worktree-per-session never receives the files — a correct run failed it. It now asserts in `<sandbox>-<slug>` and preserves that tree for debugging, as `07` and `08` already did.
- `07-chain-smoke` typed its next slash command without first clearing the dialog the previous skill had just opened, so it could be swallowed as an answer. New `drain_dialogs` in `lib/tmux.sh` answers any open dialog and waits for the pane to clear; `07` calls it at each of its three hand-offs.
- **The `Skill(<name>)` pane assertion failed correct runs for every skill the harness types.** A typed `/work` is resolved by the TUI to `/ixion:work` and loads the skill as a command; no Skill tool call is made, so no marker is rendered. Cases 05, 07 and 08 asserted it anyway — observed failing in 08 on 2026-08-21 with all nine artifact assertions passing. New `pane_ran_command` asserts the echoed command instead at those sites, which catches the failure that can actually happen there (a keystroke swallowed by an open dialog). `07` keeps `pane_has_skill_invocation` for `plan-creation`, `plan-review` and `plan-consolidation`, which `plan` loads on its own initiative and where a missing marker means what Principle 12 says.
- `plan-creation` accepted a `*-design.md` path from `plan` and `brainstorm` and had no instruction for it — `constraints[0]` would have carried a filename as the feature description. It now reads the design and records its problem statement and selected approach as `constraints[1]`.
- `brainstorm` offered `/ixion:work` as a next step; `work` cannot start without the `spec.json` only `plan` writes.
- `install_opencode.py` swapped the whole `~/.config/opencode/skills/` tree on every run, deleting any skill from another source; it now manages one directory per Ixion skill. The dead `commands/` transform path and its body rewrites are removed.
- Stale text: `(D7)` and "Cleaned on `ship`" in `plan-consolidation` (ship reads the sidecar, nothing deletes it); "harvest from 6a" in `ship`; `active.schema.json` admitted tiebreaks `session.schema.json` rejects; `progress.schema.json` described fix-findings ids as finding ids rather than theme ids; README named only the API key as a credential; `07` said `02` still sent bare `/plan`.

- **The empirical Evidence gate applies at every severity.** 3.0.0 ran the Evidence command only for P1s, so an unreproducible P1 was deleted while an unreproducible P2 went straight to `work`'s fix pass, which fixes P1 through P3 without triage. `work-review` 2.3c now gates any finding whose Failure claims runtime misbehavior and whose Evidence names a command; structural findings and `[Contradicts user]` findings are still exempt, and plan review still skips the stage. Refuted findings are dropped at every severity; ones whose command won't run drop exactly one tier (a P3 stays P3). The gate spends at most 12 commands a round, cycling one P1, one P2, one P3 and round again, so a long P1 list can't drain the budget before the lower tiers the widening was for are reached; the summary reports what went unattempted. Before deleting a refuted finding it writes the title, location and refuting output into `open_questions[]` under a `Refuted and dropped:` marker, which separates a settled record from the open questions around it and keeps a deletion auditable after the summary scrolls away.
- **`[Pattern cluster]` groups have consumer rules again.** The synthesizer has always been able to emit one group covering a shape repeated across locations, but neither consumer said what to do with it. `plan-consolidation` now treats such a group as one redesign of the `context.patterns[]` entry that generated the shape rather than N phase patches, and `work` keeps its members in a single fix theme instead of splitting them by file.
- **The gate's scope is stated once.** `ixion-conventions/SKILL.md` cited its own copy of the rule; it now cites `references/finding-format.md`, which is the single home.
- **The deferral tier is gone from the review skills' prose.** 2.0.0 removed the tier itself; the restatements that outlived it in plan review and consolidation are removed, leaving integrate-or-reject as the only model described.

## 3.0.0 — 2026-07-27

### Breaking

- **Removed the `/yolo` skill.** The autonomous orchestrator chained all six pipeline skills with every human checkpoint pre-answered. It is gone: run the skills yourself (`/plan` → `/work` → `/work-review` → `/work`), which is the flow the checkpoints were designed for. Nothing else in the plugin dispatched `/yolo`, and `work` still auto-detects fix-findings mode from session state, so no other skill changes behavior. See the amendment in `docs/adrs/0001-skill-design-as-negotiation.md` for the reasoning.
- **Removed the `pipeline[]` field from `session.schema.json`.** It was `/yolo`'s run checklist and had no other writer or reader.

### Added

- **`tests/integration/cases/07-chain-smoke.test.sh`** — drives the full chain skill-by-skill, replacing the deleted `03-pipeline-end-to-end` and `04-pipeline-smoke`. Carries forward the schema validations that existed only in `03` (consolidated `spec.json`, generated `review.findings.json`, fix-findings `progress.json`) and asserts the `/work` mode-detection transition directly. Answers the now-live `AskUserQuestion` dialogs through the harness's `autopilot_respond`, which had been dead code while `/yolo` existed.
- **Evidence slot on reviewer findings.** Findings claiming runtime misbehavior name a command that would demonstrate it, or mark themselves `unproven:`. `work-review` runs that command for P1s and drops findings that don't reproduce (new stage 2.3c). Recorded as Principle 13 in the ADR.

### Removed

- `tests/integration/cases/03-pipeline-end-to-end.test.sh` and `04-pipeline-smoke.test.sh` — both drove `/yolo` as their sole entry point; superseded by `07`.

## 2.0.0 — 2026-07-26

### Breaking

- **Renamed the plugin: flywheel → ixion.** Plugin `ixion`, marketplace `ixion-marketplace`, plugin dir `ixion/`, session state dir `.ixion/plugin/`, conventions skill `ixion-conventions`. `install_claude_code.sh` removes prior flywheel installs automatically; sessions created under `.flywheel/` are not migrated.
- **Rust-only language standards.** `language-standards` now carries Rust standards inline in its SKILL.md; the Python/TypeScript/SQL references are gone. Pipeline examples, dispatch templates, and verification commands all use the cargo toolchain.

- **Review feedback always applies.** Consolidation and fix-findings integrate every finding; the deferral tier and both P3 triage prompts are gone. The only gate left is the user's verbatim constraints — contradicting findings are rejected with a `Rejected:` note (plan) or tagged `[Contradicts user]` and skipped with a report (code).
- **Schema renamed:** `task-list.schema.json` → `spec.schema.json` (it validates `spec.json`; nothing was ever named task-list).
